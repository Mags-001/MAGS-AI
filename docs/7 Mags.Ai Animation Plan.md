# Mags.Ai Animation Plan

## 1. Purpose

The Mags.Ai website should use animation to create a premium, futuristic, interactive experience while remaining professional, readable, accessible, and performant.

Animation should support the user's understanding of the website rather than distract from the content.

**Core principle:**

> Motion should communicate hierarchy, interaction, or transition—not exist merely for decoration.

---

## 2. Hero Background

The hero section should use:

- Slow-moving purple-blue gradients
- Subtle ambient glow
- Smooth, continuous movement
- No flashing or rapid colour changes

**Purpose:** Establish the futuristic Mags.Ai identity immediately.

---

## 3. Cursor Glow

On desktop devices:

- A soft glow follows the cursor.
- Movement should be smooth with a slight delay.
- Purple-blue atmospheric effects may be used.
- The effect should be disabled on touch devices.

**Purpose:** Add interactive depth without interfering with usability.

---

## 4. Navbar Animation

When the user scrolls:

- Navbar height may reduce slightly.
- Glass blur should increase.
- Background should become slightly more opaque.
- Changes should happen through smooth transitions.

**Purpose:** Keep navigation visible while maintaining a clean visual hierarchy.

---

## 5. Hero Content Animation

On initial page load:

1. Headline gently fades/slides into position.
2. Supporting text follows.
3. CTA buttons appear shortly afterward.

Animations should remain subtle and should not delay access to important content.

---

## 6. Problem Cards

On hover:

- Slight upward movement
- Subtle gradient shift
- Soft glow or shadow
- Smooth transition

On scroll:

- Cards may gently reveal themselves as they enter the viewport.

---

## 7. Service Cards

Service cards should use the same visual interaction language as the Problem Cards:

- Subtle lift
- Gradient movement
- Soft glow
- Smooth transition
- Optional subtle icon animation

Avoid excessive bouncing, spinning, or exaggerated effects.

---

## 8. Product Cards

On hover:

- Slight scale or upward movement
- Product image/GIF preview subtly enlarges
- Border or gradient becomes more visible
- CTA becomes more prominent

Product demonstrations should not auto-play aggressively simply for visual effect.

---

## 9. Scroll Reveal

Sections may reveal themselves as they enter the viewport using:

- Fade-in
- Small vertical movement
- Progressive text reveal
- Image reveal

Animations should be short and smooth.

**Rule:** The user should notice the content first, not the animation.

---

## 10. How I Work Timeline

The process:

**Understand → Analyse → Design → Build → Test → Improve → Launch**

may animate progressively.

Possible effects:

- Timeline line progressively appears.
- Each step fades/reveals.
- The active step receives subtle emphasis.

---

## 11. FAQ Animation

FAQ interactions should remain simple:

**Question → Smooth expansion → Answer**

The open/close transition should provide clear interaction feedback without unnecessary effects.

---

## 12. Button Animation

Primary CTA buttons may use:

- Gradient sweep
- Subtle glow
- Small movement when appropriate

For example:

**Discuss Your Business Problem →**

The arrow may move slightly on hover.

Button animations must reinforce that the element is interactive.

---

## 13. Image Animation

Images may use:

- Subtle scale on hover
- Soft glow
- Border transition
- Reveal animation

Personal photographs should remain professional and should not be heavily animated.

---

## 14. GIFs and Product Demonstrations

GIFs should primarily demonstrate:

- Product functionality
- User workflows
- UI interactions
- Business processes

They should **demonstrate functionality rather than simply decorate the website.**

Large GIFs must be optimized to prevent performance issues.

---

## 15. Section Transitions

The transition between the dark futuristic hero and lighter content sections should feel intentional.

Possible techniques include:

- Gradient fades
- Soft background transitions
- Atmospheric glow
- Subtle shape or gradient movement

Avoid dramatic page transitions that make navigation feel slow.

---

## 16. Mobile Animation

Mobile should use a lighter animation experience.

Reduce or disable:

- Cursor effects
- Heavy background effects
- Large parallax movements
- Resource-heavy animations

Keep:

- Button feedback
- Card transitions
- Scroll reveals
- FAQ transitions
- Essential UI feedback

The mobile experience should remain visually rich without sacrificing performance or usability.

---

## 17. Accessibility

The website should respect:

`prefers-reduced-motion`

When reduced motion is enabled:

- Disable non-essential movement.
- Remove cursor effects.
- Minimize scroll animations.
- Keep essential interaction feedback.

The website must remain fully understandable and usable without decorative animation.

---

## 18. Performance Rules

Prefer:

- CSS transitions
- CSS transforms
- CSS gradients
- Efficient opacity animations
- Optimized images

Avoid unnecessary:

- Heavy JavaScript animation
- Constant DOM manipulation
- Very large GIF files
- Excessive blur
- Multiple simultaneous animations

Animation must not noticeably slow down the website.

---

## 19. Overall Animation Intensity

Overall animation intensity:

**Medium**

The website should feel:

**Alive → Premium → Smooth → Interactive**

Not:

**Flashy → Noisy → Overloaded**

---

## 20. Core Animation Principle

Every significant animation should have a reason for existing.

> **Motion should communicate hierarchy, interaction, or transition—not exist merely for decoration.**
