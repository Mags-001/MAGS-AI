# Mags.Ai — User Flows

**Document:** 05 — User Flows  
**Product:** Mags.Ai  
**Status:** Approved

## 1. First-Time Visitor

**Landing → Hero → Problems → About → Services → Products → How I Work → Testimonials → FAQ → Contact → Footer**

Primary journey:

> **Understand → Explore → Trust → Contact**

---

## 2. Explore a Service

**Services → Select Service → Service Details → Relevant Examples/Products → Discuss Your Business Problem**

Example:

> Business Automation → Understand what can be automated → View example → Discuss Problem

---

## 3. Explore a Product

**Products → Select Product → Product Details → Screenshots/GIF/Demo → Understand Problem & Solution → Contact / Request Demo**

Each product has a status:

- Concept
- Demo
- Live

Only relevant actions should be displayed for each status.

---

## 4. Discuss a Business Problem

**CTA → Contact Form → Submit Information → Confirmation**

After successful submission, the visitor receives a clear confirmation message.

Example:

> **Thanks! Your business problem has been received. I'll review it and get back to you.**

The system should eventually notify the Mags.Ai owner about the enquiry.

---

## 5. Direct Contact

Visitors may contact Mags.Ai through:

- WhatsApp
- Email
- LinkedIn
- Instagram

These remain secondary contact options alongside the primary contact form.

---

## 6. FAQ

**FAQ → Select Question → Answer Expands → Select Again → Answer Collapses**

The default behaviour should keep the FAQ clean and easy to scan.

---

## 7. About

**About Section → Learn About Magudeshwaran → Optional About Page**

The homepage should contain enough information for visitors to understand who Magudeshwaran is without requiring them to visit another page.

---

## 8. Testimonials / Clients

When genuine content exists:

**Testimonials → Read Testimonial → Optional Related Project/Product → Explore**

When no genuine content exists:

**Section Hidden or Clean Empty State**

No fabricated testimonials or client information.

---

## 9. Product / Demo Request

For products that are not publicly accessible:

**View Product → Request Demo → Contact Form → Product Automatically Identified**

The form should know which product the visitor is enquiring about so they do not need to explain the product again.

---

## 10. Mobile Flow

The mobile experience should preserve the same overall journey and functionality while adapting interactions for touch.

Requirements include:

- Responsive navigation
- Touch-friendly buttons and cards
- Swipe interactions where useful
- No dependence on cursor interactions
- Reduced heavy animation where necessary

---

## 11. Error & Empty States

The website should gracefully handle:

- Contact form failure
- Missing products
- Unavailable demos
- No testimonials
- No projects
- Missing/broken images
- Invalid form submissions

Users should receive clear, human-readable messages rather than technical errors.

---

## 12. Conversion Flow Principle

Every major section should provide a logical next step.

Examples:

**Problem → Explore Solution**

**Service → Discuss Problem**

**Product → View Demo**

**Product → Request Demo**

**FAQ → Contact**

**Any Major Section → Discuss Your Business Problem**

The visitor should always understand what they can do next.

---

## 13. Core User Journey

The complete experience should guide the visitor from:

> **Understanding → Problem Recognition → Exploration → Trust → Action**

The website should reduce friction between discovering Mags.Ai and starting a genuine business conversation.
